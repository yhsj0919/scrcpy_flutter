# P5-06 虚拟屏动态尺寸与应用自适应

更新于 2026-09-02。实现、连续比例 resize 和逐比例触摸真机验收均已通过，P5-06 完成。

## 实现

- 新增公开的 `ScrcpyAdaptiveDisplayController`，可嵌入宿主自己的布局。
- 预览框小于最大分辨率时按预览框尺寸处理；超过最大值时保持比例缩小。
- 支持最小尺寸、1/2/4/8/16 对齐、变化阈值和默认 250 ms 防抖。
- resize 写入串行化，避免拖动窗口时控制消息乱序。
- 创建参数始终表示 Android 虚拟屏的设备像素尺寸；Flutter 预览框默认只缩放 Texture，不修改虚拟屏。
- 工作台创建后默认保持用户填写的虚拟屏尺寸；每块屏可独立开启“动态虚拟屏”，开启后才根据预览区域发送 `RESIZE_DISPLAY`。
- 动态虚拟屏按宿主窗口物理像素计算，避免 Windows 显示缩放下误用 Flutter 逻辑像素导致分辨率过低。
- 工作台卡片跟随各自实际视频比例，横屏与竖屏不再被强制放入同一种固定比例卡片。
- 手工调整比例或切换横竖后继续保持自动适应；需要固定尺寸时由用户显式关闭。
- 关闭自动适应会取消仍在防抖队列中的 resize；单次 resize 失败不会阻塞后续请求。
- Session 关闭时先停止控制通道接收新写入，再关闭视频通道；断开后的迟到触摸或 resize 会被安全丢弃，不再写入已关闭的 Socket。
- 标题栏与操作栏分行，避免窄窗口下操作按钮挤压标题或溢出。

## 验证

- 单元测试覆盖预览框小于上限、3840×2160 等比限制到 1920×1080、极端比例、偶数对齐、防抖合并和小变化忽略。
- Xiaomi Android 16 双虚拟屏环境中，第一块屏连续切换 720×720、1024×576、576×1024、1200×400；第二块屏帧数继续增长。
- Rockchip Android 11 双虚拟屏环境中，上述四种比例分别发送中心按下/抬起事件均成功，第二块屏帧数由 2 增至 19。
- 测试前后 ADB forward 列表一致，集成测试未留下额外端口转发。
- 静态检查无问题，自适应控制器 3 项测试通过。
