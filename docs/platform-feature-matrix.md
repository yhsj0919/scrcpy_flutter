# 平台功能实现与验收矩阵

更新于 2026-09-11。

本文件用于平台适配、验收和交接。新增平台时不得重新定义功能范围，必须按相同编号逐项实现；平台存在系统限制时，填写 `[-]` 并在“平台限制”中说明原因。

状态约定：

- `[x]`：已实现并完成基本功能验证。
- `[~]`：代码已实现，等待对应平台真机验证。
- `[ ]`：尚未实现或尚未接入。
- `[-]`：平台明确不支持，已提供空实现或 `unsupportedCapability`。

只有 `[x]` 计入平台完成度。长时间稳定性、压力测试和发行构建使用独立条目，不因基本功能可用而自动勾选。

## 新平台完成规则

1. 复制“当前适配平台”中的全部编号，为新平台增加一列。
2. 先填写 `[ ]` 或 `[-]`，不得根据其他平台结果提前勾选。
3. 代码接入完成但未经目标平台验证时填写 `[~]`。
4. 完成基本验证后改为 `[x]`，并在 `docs/reports/` 记录设备、系统版本、结果和已知限制。
5. `Q03`、`Q04` 和 `R01` 独立验收，不能由功能测试替代。
